## Spec of record

Godot 4.7 project for **Roti Lezat Tycoon**, a bakery game targeting Web (itch.io, HTML5) and Android from one codebase.

**This is the `pivot-to-idle-game` branch. Here the game is an idle arcade bakery, and the authoritative specification is [docs/gdd-roti-lezat-idle-v1.md](docs/gdd-roti-lezat-idle-v1.md) (the idle GDD).** It replaces GDD v3.1 wherever they differ. Its §0 lists the v3.1 rules it keeps as they are, and for those systems [docs/gdd-roti-lezaat-tycoon-ai-ready-v3.1-final.md](docs/gdd-roti-lezaat-tycoon-ai-ready-v3.1-final.md) (GDD v3.1 FINAL) is still the reference: art direction (§4), rendering and controls (§12.2–12.4), grid and navigation (§17), the modal stack (§28.2), input (§29), the camera except the portrait framing (§30), characters (§31), furniture, interiors, neighbourhoods and street life (§32), audio policy (§33), atomic saves and three profiles (§34, §77, §106), architecture (§35), performance including MeshBake (§37, §109), English text (§43, §127), accessibility (§44), layout templates and furniture sizes (§57, §60), floor portals (§68), Decoration Mode (§72), the technical contract (§96–§101), asset origin (§111), caches, RNG and logging (§115–§117), and toolchain, runtime limits and visual spec (§128–§130). The older [docs/gdd-roti-lezaat-tycoon.md](docs/gdd-roti-lezaat-tycoon.md) is obsolete: never read it for requirements.

The maintainer's v3.1 decision log (2026-09-24 to 2026-10-25) stays in this file on `main` and in git history. The decisions that still matter here are the ones for the kept systems: the 1 in-game minute = 1 real second pace (1 sim-second = 0.5 real seconds), the flat "bantal empuk" UI kit, Sims-style Decoration Mode with wall badges, window shoppers and surprise skits (cosmetic, their own RNG), staff lines and idle gestures, the tier interiors, neighbourhoods, daylight, street life and street arrivals, the bright tutorial blink, the 10 px scrollbar gap, and the MeshBake and simulation optimizations.

The idle decisions so far: one idle mode only (no classic mode); burnt ovens and stale bread removed; the GDD v3.1 ban on offline progress (§90, §112, §113, §119) lifted; the portrait frame (idle §12.0); and the 13 decisions of idle §19, all confirmed by the maintainer on 2026-10-26. Smaller implementation choices the idle GDD left open are recorded in its **§20 (Catatan Implementasi)**; every one of them can be changed by the maintainer, and new ones go there too. If a question arises that neither GDD answers and that is more than an implementation detail, do not invent the answer silently: quote the relevant passages and get a decision from the user.

The idle GDD (narrative in Indonesian) has the product design (§1–§11: loop, economy, levels, the analytic model, offline, franchise, boosts), the UI and onboarding (§12–§14), the technical notes, save and tests (§15–§17), the English strings (§18), the confirmed decisions (§19) and the implementation notes (§20). Balance numbers live in `data/catalog/idle.json` (and `balance.json` for kept v3.1 tunables); per v3.1 §126.1, reference catalog paths instead of copying numbers into code comments or other docs.

## Project state

The idle pivot was built phase by phase on this branch (idle §17, P0–P7), one local commit per phase. Read [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for ownership and data flow, [docs/SAVE_SCHEMA.md](docs/SAVE_SCHEMA.md) for the idle save format (game mode `idle`, schema 1), and [docs/GDD_COMPLIANCE.md](docs/GDD_COMPLIANCE.md) for what is tested, merely implemented, not verified, or open. Where any doc disagrees with the idle GDD, the idle GDD wins.

Layout: `autoload/` (services, no gameplay state), `core/` (helpers, `TimeManager`, `RNGManager`, `SimManager` base), `data/catalog/*.json` (the runtime authority for all content and tuning, validated at boot by `DataRegistry`), `data/definitions/`, `gameplay/` (`SimulationRoot` plus one manager per domain), `procedural/`, `audio/`, `ui/`, `scenes/` (`main.tscn` → `PortraitShell` → `GameRoot`), `tests/`, `tools/`.

Deliberate deviation: the logging autoload is `GameLogger`, not `Logger`, because Godot 4.5+ ships a built-in `Logger` class.

The GDD narrative is Indonesian, but **all player-facing text must be English** (v3.1 §43, §127; idle §18); proper nouns such as Budi, Pak Lurah and RotiFood stay as they are. Code calls `Tx.t(key, params)`, and keys live in `data/catalog/strings_en.json`. Currency is **Koin Roti (KR)**; big numbers go through `Tx.big`/`Tx.kr`/`Tx.rate` (idle §7.5).

### Tests (run after any change)

```bash
"$G" --headless --path . res://tests/test_runner.tscn -- --skip-long         # every suite minus the long ones (~7 min; ACC_IDLE_MODEL_MATCH takes ~3)
"$G" --headless --path . res://tests/test_runner.tscn -- --only=TEST_SAVE    # by ID prefix (--id=X for an exact ID)
"$G" --headless --path . res://tests/test_runner.tscn                        # everything, including ACC_IDLE_PACING and the soaks (hours)
"$G" --headless --path . res://tools/compile_check.tscn                      # every script compiles
"$G" --headless --path . res://tools/release_validator.tscn -- --quick       # release gate without tests and exports
"$G" --headless --path . res://tools/idle_probe.tscn -- --minutes=150 --seed=101 --manage [--franchise=8] [--set="idle.path=json"]   # pacing milestones (idle §1.4)
"$G" --headless --path . res://tools/model_probe.tscn -- --hours=24 --warm=2 [--bare]   # KR/s model vs the live shop (idle §9.1)
"$G" --path . --resolution 720x1280 res://tools/ui_resolution_sweep.tscn [-- --res=720x1280 --scales=100,150 --screens=upgrades]   # idle §12.0.7 renders
```

- **Run tests and tools as scenes, never `--script`.** In `--script` mode Godot does not register autoloads, so scripts that use `DataRegistry`, `EventBus` and the rest fail to compile *silently*.
- The runner installs a custom `Logger`. Any engine or script error during a test fails it, unless the test sets `"expect_errors": true`. A GDScript runtime error does not throw, so without this a crashed test would look green. A script error inside a probe's `_ready` stops it before `quit()`, so the probe hangs: always run probes under `timeout`.
- `SimBot` (`tests/sim_bot.gd`) plays through the same APIs as the UI. With `manage = true` it plays like a typical player (best value among upgrades and recipe unlocks, saving for the next location); the pacing numbers in idle §20 come from it.
- Tests that need a quiet shop use the `tests/test_suite.gd` helpers: `tutorial.skip()`, `freeze_production`, `park_owner`, and `NEVER` (a large finite time, because `INF` is not valid JSON in saves). `jump_to_tier` and `equip_shop` build bigger shops.
- Save comparisons use `logical_state()`, because loading snaps actors to canonical cells (v3.1 §77.2, §81 no. 16). Compare saves by value (`same_state`/`diff_state`), never as JSON text: Godot can print the last digit of a tiny float (e.g. `-9.7e-17`) differently after a reload.
- The golden fixture (`tests/fixtures/golden_idle_v1.json`) changes whenever simulation or bot behaviour changes. Regenerate it on purpose with `-- --only=TEST_SAVE_001 --update-fixtures` and review the diff. Saves made by tests never contain wall-clock values: only `SaveManager.save_now` stamps `offline.last_active_unix`.
- A `GameRoot` test that boots a game lets it run at least one frame before the test sets `playing = false`, so the owner may already have paid for a batch. Assert money as a difference from a balance read inside the test, never as "equals `start_kr`".
- Achievements give a ×2 income boost and the daily coffee another; anything that compares prices or the model with the live shop must account for `boost_income_mult()` or switch boosts off (`ModelSample.no_boosts`), because the offline model is deliberately without boosts.
- Simulation-seconds are not real seconds: one real second advances `clock.sim_seconds_per_real_second` (2.0) of them (`SimulationRoot.advance`). Tests step in simulation-seconds. Any number the player reads as seconds, and every boost or promotion timer, goes through `DataRegistry.real_seconds()`.
- JSON numbers load as floats. `Array.has(3)` is false for `[3.0]`, so compare catalog arrays with `int()`.
- Never call `sort()` on arrays of StringName IDs in simulation code; use `Ids.sort` (`core/ids.gd`). `Array.sort()` orders StringName by internal address, so the same seed played out differently between sessions (`ACC_116_ID_ORDER`).
- Browsers only allow fullscreen from a finished gesture, so trigger `WebPlatform.enter_fullscreen_portrait()` on a released tap (mouse up / touch up, which is what `Button.pressed` does), never on touch-down.
- Never create a new material each time a transient visual appears (a placement ghost, a tile overlay, a marker). BaseMaterial3D frees a shader as soon as the last material with that feature combination is freed. WebGL then has to compile it again, which takes about 0.2 s with a warm browser cache and several seconds on a first visit. That is how picking furniture in Decoration Mode froze the browser. Share one material (`ProceduralMeshFactory.overlay_material`/`tint_material`). Add any new late-appearing visual to `ShaderWarmup`, so its shader compiles behind the loading screen and `MaterialKeep` keeps it alive (`ACC_89_SHADER_WARMUP`). Do not add new material feature combinations lightly. Above all, add no lit transparent material, the slowest kind to compile in a browser: thin glass is unshaded. `ACC_89_FEW_SHADERS` caps the whole game at 12 combinations. 2D effects (`FX.coin_pop`, `FX.coin_shower`) use `CPUParticles2D` with the shared coin texture.
- Never read a committed mesh back at runtime (`surface_get_arrays`): it copies the buffer back from the GPU, synchronously in WebGL. To combine generated meshes, keep `MeshBuilder.arrays()`, or build models such as characters with `MeshBuilder.capture = true` so `commit()` stores the arrays in meta `arrays` instead of uploading them (`TrafficFactory._rig`). Spread expensive generation over frames, as `StreetLife` does with `WORK_USEC`.
- The world draws baked models (`MeshBake`, v3.1 §109.3): furniture comes from `EquipmentFactory.build_cached`, bread from `BreadFactory.build_cached`/`slot_cached`, rooms through `WorldView._bake_room`. A part that moves or is looked up by name at runtime must be named in `MeshBake.KEEP_NAMES`/`KEEP_PREFIXES` or carry meta `live`, or it gets merged and stops moving. Never change a furniture material at runtime: cached prototypes share their materials. Opaque lit parts bake only when their material uses sRGB vertex colours as albedo, which `ProceduralMeshFactory.material` does; a SurfaceTool mesh bakes only when committed through `ProceduralMeshFactory.kept_commit`. Check the look with `tools/bake_compare.tscn` and the draw calls with `tools/render_probe.tscn`.
- Simulation lists are cached until their content changes: `EquipmentManager` lists until `invalidate_lists` (WorldManager.rebuild_occupancy calls it), `CustomerManager.sorted()` and `RotiFoodManager.active_orders()` as read-only arrays, and RotiFood caches through `_orders_version` (bump it on every change to `orders`). `UpgradeManager.has_room_for` caches per layout (cleared on `layout_changed`), and `IdleEconomyManager` caches the model for `CACHE_SECONDS` and the kitchen routes per layout (`invalidate()` after anything that changes income). Every simulation optimization must stay bit-identical: compare `tools/soak_trace.tscn` against the previous commit in a `git worktree`. `tools/sim_profile.tscn -- --tier=5 [--detail]` times each manager on a busy day.
- Headless Edge marks the page hidden after its first frame, so `requestAnimationFrame` stops and a Godot probe looks frozen with no error. Drive it over CDP with focus emulation (`Page.bringToFront`, `Emulation.setFocusEmulationEnabled`). Web exports exclude `tools/`, so a probe must be copied into `scenes/` for the export and removed afterwards. `tools/loading_probe.tscn` prints how long each loading stage takes; `GameRoot` logs the stages under BOOT.
- Browser hitches do not show on desktop, so measure them in a real browser. Point `run/main_scene` at a probe scene temporarily, because release templates refuse a scene path in `GODOT_CONFIG.args`. Then export Web to a scratch folder, restore `project.godot`, and serve the export. Run it with `msedge --headless=new --enable-logging=stderr --user-data-dir=<scratch dir>` and read the probe's `print()` lines from stderr. Delete the user-data dir first to get a cold GPU shader cache, like a first visit.
- To test a gesture end to end (tap, drag, right-click), push real mouse events with `runner.get_viewport().push_input(event, true)`, as `suite_56_decor_hold.gd` does. Motion events need `button_mask` set to the left button: `CommandLayer` ends a captured drag (Decoration Mode's `press_override`) as soon as a motion arrives without it. Inside the portrait shell, input reaches `GameRoot` only within the frame.
- Never rebuild a list of tappable buttons on every HUD refresh (5 times a second): a button freed between press and release loses the tap. Build them once and update their text, as `LevelChips` and the HUD boost chips do (`ACC_IDLE_LEVEL_CHIPS`: refreshing never rebuilds a chip).
- Never build a music bed in one go during play: a bed takes ~0.8 s on a desktop and several seconds in a phone browser. Use `AudioManager.request_stream`/`prewarm_music`, which assemble it slice by slice (`audio/music_build.gd`), and let the old bed keep playing until the new one is ready (v3.1 §33.6). `stream_for` still builds on the spot and is meant for short sounds.
- Never call `AudioServer.add_bus()`; add buses with `AudioServer.set_bus_count()` (`AudioManager._ensure_buses`). On Web, Godot 4.7.2 plays audio in Sample mode, and there `add_bus()` inserts the JavaScript bus in front of Master. `set_bus_send` then routes Master back into the other buses, Web Audio silences the loop, and the whole game is mute in browsers while desktop sounds fine (`ACC_33_AUDIO_BUSES`).
- "N ObjectDB instances were leaked at exit" listing `AudioStreamWAV` and `AudioStreamPlaybackWAV` means a sound was still playing when the runner quit. Godot frees a stopped playback only on a later audio mix, and shutdown can come first, so the warning appears in some runs and not others. The runner calls `AudioManager.stop_all_sounds()` and waits 0.3 s before quitting; still make sure no test leaves a sound playing. `AudioManager` lives across tests, so a test that sets `unlocked = true` must stop what it started. Every `GameRoot` game start plays the coffee chime when the coffee is poured (`check_daily_gift`).
- Read the end of the test log, not just the `TESTS:` line: a leak warning prints after it. Leaked `Control`/`Object` pairs (run with `--verbose` to see them) are orphan UI nodes, for example a `Control.new()` that is replaced before it is added to the tree. Guard UI tests with `Performance.get_monitor(Performance.OBJECT_ORPHAN_NODE_COUNT)` before and after.
- Onboarding prompts are dismissible (`tutorial.dismiss()`); `SimBot` closes them like a player. A test that needs no prompts at all calls `tutorial.skip()`. `TutorialManager.step` triggers steps from simulation state only, so it stays deterministic.
- A tool or probe that starts a game through `GameRoot` must first point `SaveManager.dir` at a test folder (as the UI tests do). Otherwise it writes the player's real desktop save slots in `user://saves`. `BoostManager.date_override` and `OfflineManager.now_override` fake the device date and clock in tests.
- Undo a temporary mutation by reapplying the reverse edit, never with `git checkout -- <file>`, which also throws away every uncommitted change in that file.
- Vertex colours read back from a committed mesh (`surface_get_arrays`) are stored with 8 bits per channel, so compare them with a tolerance of about 0.01, never with `is_equal_approx`.
- On this Windows machine, bash heredocs that contain quotes sometimes fail with "unexpected EOF"; write longer Python or GDScript helpers to a file in the scratchpad first and run that.

No linter is configured. `.github/workflows/tests.yml` runs the compile check, the tests without the long ones and the quick release validator on every push and pull request to `main`; the soaks and `ACC_IDLE_PACING` stay local.

## Engine lock (v3.1 §96, §128)

Godot 4.7-stable Standard, GDScript only, Compatibility renderer; no C#, GDExtension or third-party addons, and no APIs newer than 4.7. The installed binary is 4.7.2-stable. `project.godot` uses `gl_compatibility` (desktop and mobile), a 720×1280 `canvas_items`/`expand` stretch setup with a 540×960 desktop window, and portrait orientation (idle §12.0.1). `export_presets.cfg` holds the Web (single-threaded), Android debug APK and Android release AAB presets, with no signing secrets.

## Non-negotiable architectural constraint: 100% procedural assets

Per v3.1 §4, §12.2 and §111, **every visual in the game is generated in code**. No `.png`, `.jpg`, `.gltf`, `.fbx`, or `.obj` may be added to the project. Do not suggest importing art, downloading assets, or using placeholder sprites — generate geometry and UI instead. This is what keeps the web bundle under the 30–40 MB target and the VRAM footprint viable on entry-level Android. Audio must be original and reproducible from scripts in the repository (§111.1; it is synthesized at runtime in `audio/audio_generator.gd`), and fonts are Godot's built-in default (§111.2). `icon.svg` is generated by `tools/generate_icon.gd`, and the release validator fails if it differs.

Visual generation is split into three factory layers (§12.3):

- **`ProceduralMeshFactory`** — assembles 3D objects from `BoxMesh`/`CylinderMesh`/`SphereMesh`/`TorusMesh` + `SurfaceTool`. Equipment, bread meshes, and chibi characters are all *parameterized by tier*, so the same generator emits a Tier 1 wooden oven and a Tier 5 conveyor oven; in the idle game a station's model tier follows its level (idle §8.2). Budget 500–2000 tris per assembled object; `StandardMaterial3D` with solid colors and vertex coloring only.
- **`ProceduralAnimationSystem`** — no skeletal rigs. Locomotion is trigonometric (`sin(time * speed)` for limb swing and head nod); reactions and UI feedback use `Tween` squash & stretch.
- **`ProceduralUIFactory`** — all UI from `StyleBoxFlat` (16–24 px corner radius) plus icons drawn in `CanvasItem._draw()` (`draw_circle`, `draw_arc`, `draw_line`, `draw_colored_polygon`). Particles are `CPUParticles2D`/`CPUParticles3D` built in script. Build new UI with the §130.6 kit helpers (`button`/`apply_kind`, `icon_text_button`, `tab_bar`, `toggle`, `chip`, `badge`, `toast_card`, `empty_state`, `UIScreen.make_popup`, `UISheet.row`) instead of raw `Button`/`CheckButton`, so it matches the rest. Big screens are `UISheet` bottom sheets (idle §12.0.5). The kit is flat (§130.6): give new UI no shadows, lips, gloss, outlines or gradients, and lay out button content with `lip()`/`content_lift()`, not `LIP`. Scrollbars sit `SCROLLBAR_GAP` from their content through the theme's `scrollbar_v_separation`; a column header outside a scroll area must reserve the bar's width plus that gap, and button widths measured outside the scene tree come out about 20 px short, so size columns from in-tree sizes. Every screen must fit the 720-wide frame at 100/125/150% text without sideways scrolling (`ACC_IDLE_PORTRAIT_UI`).

## Core loop (idle §2–§6)

The shop runs **by itself, 24 hours a day** (idle §3): 1 in-game minute = 1 real second, nights 22:00–06:00 bring fewer customers, and there are no phases, no closing and no Daily Summary. Only the Pause menu and lifecycle (app or tab in the background) stop the clock.

- **Production** is automatic (idle §4.3): the owner and the bakers share `KitchenBrain`, which takes finished trays out first, moves dough into free ovens, then starts the largest affordable batch for the shelf slot with the lowest fill ratio. Each slot sells its assigned recipe or Auto (the most profitable recipe that can be made). Ingredients are paid when a batch starts. Nothing burns or goes stale (idle §4.6). The Holding Table still parks items that have nowhere to go.
- **The owner** (`PlayerTaskManager`) serves lane A while buyers wait there, otherwise cooks. A tap on a station gives it the owner's focus and a Semangat boost; a tap on the counter keeps the owner at lane A for the focus time (idle §5.1–5.2).
- **Customers** walk in from the end of the pavement (v3.1 §20.1), take bread and queue at an open lane; lane A is the owner's and every other lane belongs to one cashier (v3.1 §21.2–21.3). Window shoppers and surprises are cosmetic. **RotiFood** orders are accepted and packed automatically (idle §6.5).
- **Staff** are hired once from `staff.hire_cost` and work on their own; no wages, duty or tiers (idle §5.5).
- **Levels** (idle §8, `UpgradeManager`): stations, counter, recipes, staff and global upgrades, with ×1/×10/Max, milestones and model evolution; opening stations, unlocking recipes and moving location cost KR. Recipe levels are the main growth engine (idle §8.5).
- **KR/s** comes from the analytic model (`IdleEconomyManager`, idle §9.1), which also drives "Best value first" and offline earnings. It must stay within ±20% of the live shop (`ACC_IDLE_MODEL_MATCH`).
- **Offline** (idle §9.2–9.5, `OfflineManager`): time away earns the saved KR/s (without boosts) × min(away, cap) × efficiency; under a minute is ignored, under five minutes is credited with a toast, longer waits for Collect in the Welcome Back popup.
- **Franchise** (idle §10, `PrestigeManager`, `SimulationRoot.franchise`): from Tier 3, selling the bakery for Franchise Stars resets the run but keeps stars, perks, statistics, achievements and decorations; every star raises all income.
- **Boosts** (idle §11, `BoostManager`): Pak Lurah's coffee once per device day, paid promotions with cooldowns, and a ×2 boost from every achievement, all running only during active play.

**There is no Game Over** and no running cost besides ingredients (idle §7.3). The balance never goes below zero.

## Tier is the central progression variable

Location tier (1–5, idle §8.7, v3.1 §57) gates mixer/oven/display slot counts, checkout lanes, staff caps, queue capacity, the station level cap (`station.level_cap_by_location`), decoration slots per type (v3.1 §72.3), base arrivals and RotiFood orders, and decoration prices (`decor.price_mult_by_tier`). A recipe can be unlocked once the best mixer and oven reach its model tier (station level thresholds `station.model_tier_thresholds`). Implement all of this as data catalogs validated at boot (v3.1 §101, §134) rather than scattered constants, since the mesh factories, UI and economy all read the same tier values.

## Input, save and platform constraints

- Every gameplay action must be reachable with **one tap or one left-click**; keyboard shortcuts are optional extras. Touch targets at least 48×48 logical px, with safe-area margins (v3.1 §7, §12.4, §29, §100, §130.4).
- The whole game is drawn inside the portrait frame (idle §12.0): `PortraitShell` renders `GameRoot` in a `SubViewport` 720 logical px wide (9:16–9:21) and draws the gingham tablecloth outside it. Tests that create `scenes/game_root.tscn` directly run without the shell.
- Saves are versioned JSON with atomic temp-file writes and one backup generation (v3.1 §34, §77, §106; idle §15.3); `user://` maps to IndexedDB on web. Three independent profiles live at `user://saves/profile_N.json` plus a backup, with settings in `user://settings.json`, all implemented in `SaveManager`. Idle saves have `game_mode` `idle` and schema 1; v3.1 tycoon saves are shown as "Classic save (not supported)" and can only be deleted.
- The web build needs a "tap to start" screen so browser autoplay policy doesn't block audio (v3.1 §12.1, §33.4). Losing app or tab focus pauses the simulation and freezes the offline reference; coming back credits the time away (idle §3.4, §9.3) with no "Game Paused" screen.
- Phone browsers: `core/web_platform.gd` is the only code that talks to JavaScript (`JavaScriptBridge`); the Tap to Start tap calls `WebPlatform.enter_fullscreen_portrait()`, and a sideways phone browser gets a one-time hint (`OrientationHint`, idle §12.0.6). Tests fake a phone with `WebPlatform.force_mobile_web` and `forced_portrait`.
- Modal stack (v3.1 §28.2): opening a main blocking modal closes the other main modals and any bottom sheet. System layers set `overlay = true` (confirm, Pause menu, tutorial tips, Welcome Back, the franchise cutscene, the overflow notice): they stack on top and never close or get closed by other modals. `keep_open = true` screens close only through their own buttons. Any new popup that can appear over another modal or sheet must be an `overlay`, or it will close what is underneath.
- Entering gameplay runs in stages behind `LoadingScreen` (`GameRoot._begin_loading`/`_loading_stage`, v3.1 §89.5): each heavy step gets a frame so the bar is drawn, and `playing` only turns true once the overlay fades. A franchise rebuilds the world and HUD the same way around the same `SimulationRoot` (`GameRoot.do_franchise`).
- v1.0 is fully offline: no ads, IAP, login, backend, notifications or telemetry (idle §1; v3.1 §12.7, §112).
